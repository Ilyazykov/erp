# TODO: сглаженный числитель для Yield-метрик (Revenue/FCF/Earnings)

## Идея

Сейчас числитель Revenue/FCF/Earnings Yield считается **ступенчатой функцией**:
последнее опубликованное годовое (или TTM) значение держится константой до
публикации следующего отчёта, когда происходит мгновенный скачок.

Предлагаемая замена:

1. **Предсказать следующую (ещё не опубликованную) точку** конкретным методом
   прогнозирования — метод зависит от типа метрики (см. таблицу ниже).
2. Добавить эту предсказанную точку в набор данных как обычную точку.
3. Построить **один** натуральный кубический сплайн (`scipy.interpolate.CubicSpline`,
   `bc_type="natural"`) через **все** точки — реальные отчётные + одну предсказанную.
4. Использовать значение сплайна на каждую дату как новый, гладкий числитель.
5. Когда выходит реальный отчёт — предсказанная точка заменяется на настоящую,
   и весь сплайн (и вся производная история Yield/Z-score) пересчитывается заново.

Визуальный референс (уже реализовано и проверено для VKCO как прототип, см.
`erp_valuation/vkco_zscore_experiment.py`, колонки `revenue_yield_v2` /
`z_score_v2` / `revenue_v2_bln` в `data/vkco_zscore.csv`):
- `tmp_charts/vkco_new_logic_proposal.png` — общая идея на одном графике
- `tmp_charts/vkco_new_yield_with_revenue.png` — числитель + Yield одновременно,
  старая (ступенька) и новая (сплайн) логика side-by-side
- `tmp_charts/vkco_backtest_method*.png` (10 файлов) — честный backtest
  (без заглядывания вперёд) каждого из 10 кандидатных методов прогноза

## Честный backtest: какой метод выбирать для прогноза следующей точки

Прогнали 10 методов прогнозирования на всех тикерах с достаточной историей
(`data/annual_extra.csv`, `data/vkco_annual_revenue.csv`, `data/quarterly_ni.csv`),
честно — на каждом шаге модель видела только данные "как если бы" это было
известно на тот момент (no look-ahead), и сравнивали ошибку с фактом, когда он
появился. Метрики: MAE и MSE, нормированные на прогноз "наивным" методом
(последнее значение = прогноз) как базовую линию.

### Итоговая сводная картина по всем типам метрик

| Тип метрики                              | Лучший метод                     |
|-------------------------------------------|-----------------------------------|
| Revenue (растущие компании)                | 5/6 (процентные, CAGR)            |
| FCF (капиталоёмкие/цикличные)              | 1 (Naive)                         |
| Earnings/net income (банки, энергетика)    | 8 (Weighted LinReg)               |

Тикеры, использованные для калибровки:
- **Revenue**: VKCO, YDEX, OZON
- **FCF**: ROSN, GMKN, PLZL (YDEX fcf исключён из финального теста — содержит
  отрицательные значения, ломает часть методов и не относится к этой тройке)
- **Earnings (net income)**: SBER, T, VTBR, IRAO — поквартальный net income
  (TTM пока не использовали, тестировали прямо на квартальных точках,
  пропуски 2022 года у SBER/VTBR из-за отсутствия отчётности исключены,
  оставшиеся кварталы переиндексированы последовательно без учёта разрыва)

### Описание 10 методов (полные формулы — в истории чата/скриптах `/tmp/plot_vkco_*backtest*.py`, не сохранены в репозитории)

1. **Naive** — прогноз = последнее известное значение (флэт)
2. **LinReg all-years** — обычная (невзвешенная) линейная регрессия по всей истории
3. **LinReg last-5y** — линейная регрессия только по последним 5 точкам
4. **Avg abs change** — среднее абсолютное изменение за последние 5 периодов, прибавленное к последнему значению
5. **Avg growth rate** — среднее арифметическое всех годовых мультипликативных отношений (ratio), применённое к последнему значению
6. **Strict CAGR** — единый компаунд-темп роста между самой первой и самой последней точкой истории (`CAGR = (y_last/y_first)^(1/n) - 1`)
7. **Cubic spline extrapolation** — натуральный кубический сплайн через все точки, продолженный по своей кривизне на один шаг вперёд (математически некорректно для экстраполяции — стабильно худший или почти худший метод везде)
8. **Weighted LinReg** — линейная регрессия с экспоненциальными весами по давности (`weight_i = λ^(лет назад)`, изначально λ=0.75, калибровка показала оптимум ближе к 0.8-0.95 в зависимости от ряда — см. ниже)
9. **Windowed CAGR** — тот же принцип, что метод 6, но окно ограничено последними 6 годами (5 периодов) вместо всей истории
10. **Weighted growth rate** — взвешенное (по давности) среднее геометрическое годовых отношений — версия метода 5 с весами

### Калибровка λ для метода 8 (Weighted LinReg)

Не бралось "на глаз" λ=0.75 — сделали honest backtest по сетке λ от 0.05 до 1.0
с шагом 0.001 в области оптимума:

- **VKCO (revenue)**: оптимум по MAE — λ≈0.907, но кривая ОЧЕНЬ плоская в диапазоне
  0.85–1.0 (различия в 4-м знаке после запятой = статистический шум на 10 точках).
  По MSE оптимум строго λ=1.0 (т.е. вообще не взвешивать).
- **SBER (net_income)**: похожая картина, оптимум по MAE λ≈0.80, по MSE снова λ=1.0.
- **GMKN (fcf)**: единственный ряд, где взвешивание реально помогает — оптимум
  λ≈0.6-0.7, выигрыш ~6% по MAE относительно λ=1.0. Такие ряды (хаотично
  волатильные без устойчивого тренда) — редкое исключение, где recency-weighting
  окупается сильнее.

Вывод: **фиксированное λ=0.75 не обосновано** — если метод 8 будет использоваться
в production (для Earnings/net income, где он объективно лучший), стоит либо
откалибровать λ отдельно под каждый тикер/метрику через тот же backtest-скрипт,
либо просто взять λ в диапазоне 0.8-0.9 как разумный компромисс.

## Ключевые технические детали (чтобы не переизобретать)

- Дата публикации годового отчёта за год `Y`: `date(Y + 1, 3, 1)` (везде в
  проекте — `annual_report_date()`), используется как x-координата точки в
  сплайне.
- Сплайн требует минимум ~4 точки для естественных граничных условий
  (`bc_type="natural"`); при меньшем числе точек — fallback на линейную
  интерполяцию между двумя ближайшими известными точками (см.
  `get_smoothed_annual_revenue()` в `vkco_zscore_experiment.py`).
- Сплайн строится один раз на **весь** диапазон (все реальные точки + 1
  предсказанная), а не "по кускам" — иначе будет look-ahead bias или разрыв
  на стыке истории и прогноза (мы дважды наступали на эти грабли в процессе
  разработки, см. историю чата про "заглядывание вперёд" и про "угол на
  графике").
- MAE честно считается только на прогнозах, для которых уже известен факт
  (последний "открытый" прогноз — например, 2026 год для VKCO — не участвует
  в расчёте ошибки, так как факта ещё нет).
